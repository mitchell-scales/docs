A workflow is a **modular routine of processing data** where you can perform actions on it — materialise it, send it elsewhere, process it in specific ways, interact with it through AI, or set up chatbots, among others.

<Tip>
  Workflows are often created directly from a [dataset](/datasets) (Materialization or Google Sheets), or triggered from inside a [report](/making-a-report) via an Action element.
</Tip>

## The Workflows Table

Each row lists a workflow and the key information you need to understand what it's doing and how it's performing.

| Column | Description |
| --- | --- |
| **Workflow** | Title and description of the workflow. |
| **Trigger** | What sets the workflow off — e.g. cron schedule, manual. |
| **Last Status** | Status of the most recent run. |
| **Last Ran** | When the workflow last ran. |
| **7-Day Health** | Status composition of runs over the last seven days. |

<Tip>
  Hover over a segment of the **7-Day Health** bar to see the status of that individual run — useful for spotting exactly when a workflow started failing.
</Tip>

### Row Actions

Each row offers two ways to take further action.

<Columns cols={2}>
  <Card title="Folder icon" icon="folder-open">
    View the latest run.
  </Card>

  <Card title="Options menu (⋮)" icon="ellipsis-vertical">
    Opens further actions — see below.
  </Card>
</Columns>

The options menu (⋮) covers the following:

| Action | Description |
| --- | --- |
| **Open workflow** | Opens the workflow for editing. |
| **Share** | Shares the workflow with others. |
| **View instructions** | Shows the workflow's configured instructions. |
| **View saved values** | Shows the values saved by the workflow. |
| **Update tags** | Edit the workflow's tags. |
| **Run now** | Triggers an immediate run. |
| **Rerun failed tasks** | Reruns only the tasks that failed in the previous run. |
| **Delete** | Deletes the workflow. |
